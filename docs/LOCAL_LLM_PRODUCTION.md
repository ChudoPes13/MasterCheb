# Локальная Маша: запуск и границы проверки

Обновлено 9 сентября 2026. Рабочий вариант использует существующую Ministral 3 3B Instruct Q5_K_M на RTX 3070 Laptop 8 ГБ, без платных API. Это локальная модель, а не подключение к модели Codex из рабочего диалога владельца.

## Запуск

Ярлык «МастерЧеб — запуск backend» открывает видимую консоль. `scripts/start-backend.ps1` запускает локальную LLM, если порт 8080 свободен, ожидает модель и запускает backend. Логи LLM находятся в игнорируемой `.runtime`, консоль backend остаётся открытой. При выключении backend отдельный процесс LLM остаётся запущенным; повторный запуск его использует. Nginx и автозапуск Windows этот скрипт не настраивает.

Отдельный запуск модели:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\ai26\MasterCheb\scripts\start-llm.ps1
```

Фактический путь модели: `C:\ai25\v2v_RAG_gpt52\Ministral-3-3B-Instruct-2512-Q5_K_M.gguf`. Путь с вложенными `_RAG\_gpt52` из первоначальной команды на этом ПК не найден.

| Настройка | Рабочее значение | Причина |
|---|---|---|
| GPU layers | 99 | Все слои этой модели на GPU |
| Context / parallel | 12288 / 3 | По 4096 токенов на каждый из трёх слотов |
| Batch / ubatch | 512 / 256 | Запас памяти для Whisper, Silero и дисплея |
| KV cache | q8_0 / q8_0 | Умеренный объём кеша трёх контекстов |
| Flash attention | on | Эффективное внимание на CUDA |
| Threads / batch threads | 8 / 8 | Соответствует исходной конфигурации ПК |
| Listen | 127.0.0.1:8080 | Модель не открыта посетителям напрямую |

Совместно с голосовым backend наблюдалось около 4,9 ГБ занятой VRAM и около 3,1 ГБ свободной. Это проверенная рабочая конфигурация с запасом; исчерпывающего сравнения всех batch/quantization параметров не проводилось. Увеличивать контекст/параллелизм без повторного нагрузочного прогона не следует.

## Сценарий Б и факты

`config/masha_scenario.txt` задаёт предметный диалог: ответ по текущему вопросу, один уместный следующий шаг, проверка примера задачи, уточнение канала и предложение консультации. История используется для уточнений; заявка не предлагается повторно после отказа. Простое приветствие и буквальные поля заявки обрабатывает приложение.

LLM возвращает JSON по схеме: намерение, основную тему, короткую реплику и следующий шаг. Обычный вопрос не может содержать действие записи поля в схеме. Числа, цены, условия и другие ответы выбранной темы выводятся из `docs/rag/mastercheb.jsonl`. Свободный текст используется для небольших разговорных реплик и уточнений; формат, язык и некоторые опасные обещания дополнительно проверяются. LLM не может самостоятельно отправить заявку или подтвердить встречу.

Примеры основных ответов:

- Материалы: первоначальное наполнение базы в любом формате примерно до тысячи страниц включено в базовые тарифы; сложные материалы обсуждаются при согласовании.
- Доверие: внедрения у нескольких клиентов есть, но имена и детали закрыты; публичные количественные результаты не предоставлены.
- Голос: отдельный проект может воссоздать голос по образцу с разрешения его владельца, демонстрация по запросу; качество и сходство оцениваются на фразах клиента. Сейчас русский голос — `kseniya`.
- Оплата: условия обсуждаются лично с Александром; действующие согласованные условия сохраняются до отдельно согласованных изменений.
- Отказ: сбор заявки прекращается, разговор можно продолжить.

При недоступности LLM действует существующий лексический FAQ. Он не равнозначен контекстной модели. Одна модель 3B и конечный набор проверок не гарантируют понимание любого запроса: свободная беседа, неоднозначные отрицания, длинная история и несколько тем остаются предметом дальнейшей оценки. По умолчанию генеративный маршрут выбирает одну основную тему, чтобы не смешивать случайные соседние ответы; он не является универсальным многошаговым агентом с доступом к CRM или действиям клиента.

## Очередь и голос

`TurnQueue`: три активных ответа, до 24 ожидающих, FIFO. Слот охватывает распознавание, LLM, синтез/доставку и подтверждение окончания проигрывания клиентом. Подключённый молчащий посетитель не занимает вычислительный слот. STT и Silero используют защищённые общие очереди для безопасной работы моделей; это не обещание одновременного исполнения трёх CUDA-ядер синтеза.

Новый браузерный протокол — `hello.protocol=2`, `voice_response=true` по умолчанию. Пользователь видит позицию ожидания и может отменить ожидание. Токен ответа связан с сессией; чужое подтверждение не освобождает слот. Отмена, отключение и таймаут освобождают очередь. Ожидание места ограничено 90 секундами, обработка/доставка — 60 секундами, подтверждение проигрывания — ещё 90 секундами. Последнее ограничение защищает от зависших вкладок, но не служит договорным SLA. Браузер отправляет heartbeat каждые 25 секунд.

Озвучка включена до первого приветствия. Остаток PCM менее 3200 отсчётов отправляется перед завершением записи. При остановке озвучки аудио отменяется, а новые чанки не проигрываются до нового ответа. Старые клиенты без protocol=2 совместимы по тексту/озвучке, но не подтверждают длительность проигрывания.

## Проверки

- 90 тестов: прежние регрессии, очередь/отмена/изоляция, реальные значения полей, ограничение действий LLM, ударение фамилии.
- `scripts/evaluate_local_dialog.py`: 22 синтетических реплики в RU/EN/ZH, первые три диалога параллельно. Результат сохраняется только в игнорируемой `output/local-dialog-evaluation.json`; это материал для оценки качества, а не доказательство правильности всех ответов. По найденным сбоям добавлены прикладные ограничения и регрессии.
- `scripts/verify_turn_capacity.py --with-stt`: четыре синтетические сессии, четвёртая ждёт освобождения места после подтверждения проигрывания; затем три параллельных текстовых и три голосовых запроса. В последнем прогоне доставка озвучки текстовых запросов заняла 3,61–3,98 с, голосовых — 3,17–4,39 с. Это короткие лабораторные фразы; время записи человеком и реального проигрывания не включено в эти измерения. Синтетические сессии этого скрипта удаляются адресно; чужие сессии не читаются.
- 47 публичных фраз заново синтезированы в 48 кГц: ошибок синтеза и необработанной латиницы нет. Выполнено обратное распознавание. Фамилия нормализуется как `М+астеров`, ударение подтвердил владелец.
- Публичный браузер: приветствие запускает воспроизведение автоматически, «Ответ голосом» включён; получен голосовой ответ о первоначальном наполнении базы. На 390 px нет горизонтального переполнения, согласие 13 px; на 1440 px тарифные пункты 14 px, FAQ 17 px.

Физический микрофон Samsung S24, шум/эхо и полная слуховая приёмка человеком не проверены. Браузер может ограничивать autoplay; интерфейс сообщает об ошибке, текст остаётся доступным. Для оценки произношения используется локальная галерея `output/pronunciation-audit/index.html`; ASR не проверяет ударение на слух.

## Источники решений

Параметры запуска сверены с установленным `llama-server --help` и [официальной документацией llama.cpp server](https://github.com/ggml-org/llama.cpp/tree/master/tools/server). Модель — [официальная Ministral 3 3B Instruct](https://huggingface.co/mistralai/Ministral-3-3B-Instruct-2512). Короткий ответ, один вопрос и учёт контекста опираются на [Google Conversation Design](https://developers.google.com/assistant/conversation-design/learn-about-conversation); постепенное выяснение задачи без длинного опроса — на [практику discovery Gong](https://www.gong.io/blog/sales-discovery-questions). Эти материалы использованы как рекомендации по поведению, а не как доказательство результатов МастерЧеб.
