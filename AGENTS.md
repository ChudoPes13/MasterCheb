# Правила работы с МастерЧеб

## Контекст и требования владельца

- Создатель: Мастеров Александр Владимирович. Бренд произносится «Мастер Чеб»; прежний бренд не использовать в публичных текстах.
- Цель: сайт сам демонстрирует возможности помощника и приводит посетителя к контакту или заявке на консультацию. Александр связывается вручную; агент не подтверждает встречу самостоятельно.
- Маша: обращение на «вы», простой деловой стиль, не более трёх предложений в ответе. Русский голос `kseniya`.
- Языки: русский по умолчанию, английский, китайский (мандаринский, zh-CN).
- Подписка от 50 000 ₽/месяц; On-Prem от 250 000 ₽ без оборудования. Консультация бесплатна; демонстрация 1–3 дня по запросу; внедрение обычно 1–3 недели.
- On-Prem: контроль, поддержка и обновление базы первые два месяца. Подписка: сопровождение в оплаченный месяц.
- Индивидуальные интеграции и сложные расчёты обсуждаются с Александром. Не обещать, что демонстрация уже реализует любую задачу.
- Никаких платных API. Дополнительные расходы согласовать; ранее обозначенный бюджет 1445 ₽ не считать актуальным балансом без проверки.
- Текст диалога сохраняется, аудио не сохраняется. Не включать контакты клиентов и содержимое сессий в Git или отчёты.

## Уточнения владельца от 9 сентября 2026

- Фамилия создателя произносится «Ма́стеров»; в Silero используется `М+астеров` с сохранением падежного окончания.
- В базовые тарифы входит первоначальное наполнение RAG: любые форматы, примерно до 1000 страниц. Последующие обновления — в рамках согласованного сопровождения.
- Есть внедрения у нескольких клиентов, но их имена и детали проектов раскрывать нельзя. Подтверждённые публичные количественные результаты не предоставлены.
- Оплата и договор обсуждаются лично с Александром. Для действующих клиентов текущие согласованные условия продолжаются, если изменения отдельно не согласованы.
- Текущий ПК: RTX 3070 Laptop 8 ГБ, локальная Ministral 3 3B Q5_K_M; минимум три одновременных обрабатываемых диалога, остальные в очереди с учётом озвучки. RTX 5080 — возможный будущий апгрейд.
- Ответ голосом включён по умолчанию. Основной голос русский; другие языки и индивидуальная озвучка — по запросу. Копирование голоса относится к TTS, требует разрешения владельца голоса; сходство и качество оцениваются на демонстрации.
- Сценарий Б: короткий полезный ответ, затем один уместный вопрос; показать работу Маши на реальной задаче, затем предложить консультацию, без повторного давления после отказа.

## Дизайн и интерфейс

- Основной дизайн — тёмный вариант 2. В текущем коде варианты 1 и 3 доступны по query-параметру для сравнения; это состояние реализации, а не требование сохранять три дизайна навсегда.
- Сохранять удобство вертикальной версии телефона. Проверять также desktop: FAQ, контакты, чат и подписи должны быть читаемыми.
- Финальный блок «Подготовить заявку» удалён по просьбе владельца. Сбор заявки в чате остаётся.
- Допустимы лёгкие анимации с учётом prefers-reduced-motion.
- Голос: нажать, говорить, дождаться паузы; ручное завершение не должно быть обязательным.

## Выполнение работ

- Перед продолжением прочитать README.md, docs/PROJECT_STATUS.md и docs/RUNBOOK.md; проверить фактический Git и процессы.
- Не изменять исходный проект UmMachine_2; его Python-окружение пока используется как резервное.
- Не перезаписывать чужие изменения и не добавлять весь workspace через `git add .`: каталог `outputs/` содержит отдельные артефакты.
- Не публиковать .env, ключи, сертификаты, модели, SQLite, сессии или файл с реквизитами ИП. Секреты не выводить в лог инструментов.
- Владелец ранее разрешил публикацию на Jino и push в main в рамках запрошенных изменений; повторного подтверждения этих действий не требовать.
- Проверять результат публикации извне: HTML должен ссылаться на текущие ассеты, JS/CSS должны возвращать 200; дополнительно проверить браузер и API.
- Не называть тесты доказательством правильности любых ответов. Сначала воспроизводить неверные ответы, затем исправлять и добавлять регрессионные сценарии.
- Управлять браузером по актуальному состоянию окна и документации инструмента. Не повторять клики по устаревшим координатам.
